# 데모 시연 대본 (Demo Scenario)

> 상태: ✅ 확정 · 최종수정: 2026-08-06

발표자가 그대로 따라 읽어도 되는 수준의 실행 대본이다. 화면 이름·경로·버튼 문구는
실제 코드·각 레포 README를 확인해 적었다. 5분/15분 두 코스로 구성하며, 15분 코스는
5분 코스를 포함해 확장한다.

> 이 문서는 공개본이라 구현 레포로 가는 링크와 개발 머신에 종속된 실행 절차는
> 일반화했다. 실행 명령은 각 레포의 README가 정본이다.

## 1. 사전 준비

기동 순서는 의존관계를 따른다 — DB → 서버 → 웹.

| 순서 | 구성 요소 | 명령 |
|---|---|---|
| 1 | DB | `podman start ssw-e-commerce-demo-mariadb` |
| 2 | 서버 | `ssw-e-commerce-demo-server`에서 `DB_USER=... DB_PASSWORD=... ./gradlew bootRun` |
| 3 | 웹 | `ssw-e-commerce-demo-web`에서 `npm run dev` |
| 4 | 관리자 웹 | `ssw-e-commerce-demo-admin-web`에서 `npx next dev` |
| (선택) | 관리자 Windows | `dotnet run --project src/SswEcommerceAdmin.Wpf` (`ssw-e-commerce-demo-admin-windows`) |
| (선택) | 안드로이드 | 에뮬레이터 기동 후 앱 실행 |

> ⚠️ **DTO·엔티티(Lombok 어노테이션 붙은 클래스)를 수정한 뒤 서버를 재기동할 때는
> `./gradlew clean`을 한 번 돌리고 `bootRun`한다.** 어노테이션 프로세서 캐시가 남아 있으면
> 새 필드의 getter/setter를 못 찾는 컴파일 오류가 날 수 있다(서버 README 명시 사항).

`.claude/launch.json`에 web·admin-web·server 세 실행 설정이 등록돼 있어 로컬에서는
이 설정으로 바로 띄울 수 있다.

### 데모 계정 (4종, 공통 비밀번호 `<데모 비밀번호>`)

| 이메일 | 역할 | 주 사용처 |
|---|---|---|
| `customer@demo.ssw` | `CUSTOMER` | 고객 웹 · 안드로이드 |
| `admin@demo.ssw` | `ADMIN` | 관리자 웹 · Windows (전권) |
| `seller@demo.ssw` | `SELLER_SUPPORT` | 관리자 웹 · Windows (Windows 앱 주 사용 역할) |
| `cs@demo.ssw` | `CUSTOMER_SUPPORT` | 관리자 웹 (문의 답변) |

고객 웹 로그인 화면은 `customer@demo.ssw` 칩 하나만 자동 채움을 지원하고, 관리자 웹
로그인 화면은 staff 3계정(admin/seller/cs) 칩을 모두 제공한다. `CUSTOMER` 계정은
관리자 웹·Windows 앱에서 로그인 자체가 거부된다.

> 외부 시연용으로는 별도의 **시연 전용 관리자 계정**이 공용 인프라 auth에 등록돼 있어,
> 로컬 시드 계정과 달리 **인프라 위임 경로(RS256)로 실제 인증**된다(인프라가 불통일 때만
> 로컬 폴백). 자격증명은 레포에 두지 않고 오너가 별도로 전달한다.

### 자체 LLM 서빙 서버 (선택 — 켜져 있지 않아도 시연 가능)

챗봇(고객 웹)·AI 브리핑·문의 초안(관리자 웹) 3개 기능이 `<자체 LLM 서빙 서버>`
(OpenAI 호환, gemma 26B)에 의존한다. **평소에는 꺼져 있는 것이 기본 상태**이고 오너가 필요할
때만 켠다. 모델 가동 여부는 `/v1/models`로 자동 감지하며, 응답이 없으면 3개 기능 모두
**오프라인 폴백**(규칙 기반의 제한된 응답)으로 자동 강등된다 — 다른 화면은 영향 없다.
**LLM 서버가 꺼져 있어도 5분/15분 코스 전체가 그대로 동작한다.**
(네 번째였던 실험실 — 자연어 통계는 워커 이관과 함께 비활성됐다. 15분 코스 24번 참고.)

## 2. 5분 코스 (핵심)

핵심 커머스 플로우 → 관리자 반영 확인 → 멀티플랫폼 마무리 순서다.

### 고객 여정

**1. 홈 (`/`)**
히어로 배너와 추천 섹션(신상품·세일 등)이 있는 첫 화면이다.
> 여기서 보여줄 것: 첫인상 완성도. "추천"이 실제 시드 데이터 기반으로 구성된다는 점.

**2. 카탈로그 (`/catalog`)**
상단 정렬바 우측의 보기 전환 토글(▦ 그리드 / ☰ 리스트, 접근성 라벨 "그리드 보기"·"목록 보기")을 클릭한다.
> 여기서 보여줄 것: 그리드 ↔ 리스트 전환 애니메이션.

**3. 상품 상세 (`/products/{id}`)**
리뷰 영역에서 포토 리뷰 썸네일을 클릭해 라이트박스를 연다(← → 키로 다음/이전 사진 이동,
Esc로 닫기). 아래로 스크롤해 관련 상품 섹션을 보여준다.
> 여기서 보여줄 것: 포토 리뷰 확대·키보드 내비게이션, 관련 상품 추천.

**4. 장바구니 (`/cart`)**
쿠폰 영역에서 코드를 등록하거나(플레이스홀더 예시: `WELCOME10`) 보유 쿠폰 중 하나를 선택해
적용한다.
> 여기서 보여줄 것: 쿠폰 적용 시 할인 금액이 즉시 재계산되는 것.

**5. 결제 (`/checkout`)**
결제 수단(신용/체크카드·계좌이체·휴대폰) 중 하나를 고르고 **"결제하기"** 버튼을 누르면
**SSW PAY** 모달(헤더에 "DEMO PAYMENT GATEWAY"·"TEST MODE" 배지)이 뜬다. **"결제 승인"**을
클릭한다.
> 여기서 보여줄 것: 모달에 적힌 "가상 결제창입니다. 실제 결제나 금융 정보 입력은 발생하지
> 않아요" 문구 — 목업임을 화면으로 직접 각인.

**6. 주문완료 (`/complete`) → 주문 상세 (`/orders/{id}`)**
주문 상세로 이동해 상태 타임라인(대기 → 결제완료 → 배송중 → 배송완료)을 보여준다.
> 여기서 보여줄 것: `ORD-YYYY-NNNNNN` 형식의 주문번호, 타임라인 시각화.

### 관리자 여정

**7. 관리자 웹 로그인 (`/login`)**
staff 데모 계정 칩에서 **admin@demo.ssw**를 클릭해 로그인한다.

**8. 주문 관리 (`/orders`)**
칸반 보드에서 방금 만든 주문 카드를 다음 상태로 전이시킨다.
> 여기서 보여줄 것: 상태 전이가 상태머신을 따른다는 점(취소는 대기·결제완료 상태에서만 허용).

**9. 리뷰 관리 (`/reviews`)**
리뷰 하나를 블라인드 처리한 뒤, 고객 웹 상품 상세를 새로고침해 그 리뷰가 목록에서 빠진
것을 보여준다.
> 여기서 보여줄 것: 관리자 조작이 고객 화면에 곧바로 반영되는 것.

**10. 대시보드 — AI 브리핑 (`/dashboard`, LLM 서버 켠 경우)**
대시보드 상단 AI 브리핑 카드가 매출·주문·재고 지표를 요약한 문장을 보여준다.
> 여기서 보여줄 것: LLM 서버가 켜져 있을 때만 나오는 개인화 브리핑. 꺼져 있으면 이 스텝은
> 건너뛰거나 오프라인 폴백 문구를 그대로 보여주는 쪽으로 대체한다(3절 시연 팁 참조).

### 마무리 — 안드로이드 앱 셸

**11. 안드로이드 앱**
에뮬레이터에서 앱을 실행하고 하단 네이티브 탭(홈·카테고리·장바구니·찜·마이페이지)을
오간다.
> 여기서 보여줄 것: 화면 자체는 고객 웹을 그대로 띄우면서, 하단 탭은 네이티브로
> 동작하고 URL 라우트가 유지되는 것.

## 3. 15분 확장 코스

5분 코스(1~11단계)에 이어서 진행한다.

### 고객 웹 — 부가 기능

**12. 알림함**
고객 웹 헤더의 벨 아이콘을 열어 주문/배송 알림 목록을 보여준다.
> 여기서 보여줄 것: 안 읽은 알림 개수 배지, 알림 종류(주문·배송 상태 변경 등).

**13. 1:1 문의 왕복**
고객 웹 `/inquiries`에서 "새 문의 작성"으로 문의를 남긴다. 관리자 웹 `/inquiries`에서
해당 문의를 열어 **"AI 초안"** 버튼(LLM 서버 켠 경우 답변 초안을 입력란에 채워줌 — 자동
등록은 되지 않는다)을 눌러보고 답변을 등록한다. 고객 웹으로 돌아와 상태가 "답변 완료"로
바뀐 것을 확인한다.
> 여기서 보여줄 것: 고객 ↔ 관리자 화면을 오가는 왕복 자체, AI 초안은 초안일 뿐 사람이
> 검토 후 등록한다는 것.

**14. 배송지 자동채움**
`/mypage/addresses`에서 배송지를 기본 배송지로 지정한 뒤 `/checkout`으로 이동한다.
> 여기서 보여줄 것: "기본 배송지는 결제 화면에 자동으로 채워져요" 그대로 입력란이
> 자동으로 채워지는 것.

**15. 최근 본 상품 · 쿠폰함 · 매장 안내**
`/recently-viewed`(최근 본 상품) · `/coupons`(쿠폰함) · `/stores`, `/stores/{id}`(매장 안내)를
짧게 훑는다.
> 여기서 보여줄 것: 마이페이지 하위에 흩어진 부가 화면들이 실제로 다 동작한다는 것.

**16. 결제 실패/취소 분기**
체크아웃에서 SSW PAY 모달의 **"결제 실패 (테스트)"** 버튼을 눌러 실패 처리를 보여준다
(주문이 생성되지 않는다). 이어서 주문 목록(`/orders`)에서 대기·결제완료 상태 주문의
**"주문 취소"** 버튼을 보여준다.
> 여기서 보여줄 것: 성공 경로만이 아니라 실패·취소 분기도 실제로 다뤄진다는 것.

**17. 소셜 가상 로그인**
로그아웃한 뒤 로그인 화면에서 소셜 버튼 4종(네이버 · 카카오 · Google · Meta) 중 하나를 누른다.
공급자 창으로 나가는 대신 **가상 로그인 모달**이 뜨고, 승인하면 데모 계정으로 실제 로그인이
완료돼 메인(`/`)으로 이동한다.
> 여기서 보여줄 것: "OAuth 콜백이 성공했다고 가정한 지점부터" 이어붙인 구조라는 것을 그대로
> 설명한다. 데모에 외부 공급자 앱 등록·키·시크릿을 끌고 들어오지 않으려고 **의도적으로 자른
> 경계**이고, SSW PAY 결제 모달과 같은 계열의 가상 연동이다. 모달 뒤의 로그인은 목업이 아니라
> 실제 JWT 발급이라, 이후 화면 흐름은 일반 로그인과 완전히 같다.

### 관리자 웹 — 운영 편의

**18. 커맨드 팔레트**
관리자 웹 어디서든 `Ctrl+K`(Mac은 `Cmd+K`)를 눌러 팔레트를 열고 화면 이름으로 검색해
이동한다.
> 여기서 보여줄 것: 최근 사용한 메뉴가 우선 노출되는 것, 마우스 없이 이동하는 속도감.

**19. CSV 내보내기**
주문 관리 또는 상품 관리 화면에서 목록을 CSV로 내려받는다.
> 여기서 보여줄 것: 화면에 로드된 페이지가 아니라 현재 필터 조건 전량이 내려받아지는 것.

**20. 재고 위젯**
대시보드 하단의 재고 부족/품절 위젯을 보여준다.
> 여기서 보여줄 것: 재고가 위험 수준인 상품이 한눈에 걸러지는 것.

**21. 감사로그**
대시보드 하단 운영 이력 타임라인을 보여준다.
> 여기서 보여줄 것: **주문 상태 변경 이력만** 기록한다는 점 — 리뷰 블라인드 처리 같은
> 조작은 별도 감사 이력 모델이 없어 여기 포함되지 않는다. "주문 상태 변경만 추적한다"고
> 정확히 짚어주는 편이 좋다.

**22. 주문 상태 변경 히트맵**
대시보드 "주문 집중 시간대" 카드(요일 × 3시간 단위 집계)를 보여준다.
> 여기서 보여줄 것: 320건 시드 주문이 실제 분포를 만들어낸다는 것.

**23. 라이브 시연 모드**
대시보드 우상단 "라이브 모드" 토글을 켠다.
> 여기서 보여줄 것: 실시간으로 주문이 들어오는 것처럼 매출·주문 수가 움직이는 연출
> (실제 신규 데이터가 아니라 시연용 연출임을 알고 진행한다).

### AI 기능 (LLM 서버 켠 경우)

**24. AI 브리핑 · 문의 답변 초안**
대시보드에서 AI 브리핑을 생성해 지표 요약을 받고, 문의 답변 화면에서 답변 초안을 생성한다.
> 여기서 보여줄 것: 화면에 이미 떠 있는 운영 데이터를 근거로 문장이 만들어지는 것.
> LLM 서버가 꺼져 있으면 규칙 기반 폴백으로 내려가는 것까지 그대로 보여준다.

> 🚧 **실험실의 자연어 통계(`/labs/nl-stats`)는 현재 시연할 수 없다.** 관리자 웹을
> Cloudflare Workers로 옮기면서 비활성됐다 — MariaDB에 TCP로 직결하던 기능이라 워커
> 런타임에서 성립하지 않는다. 질문이 나오면 "SQL을 LLM에게 짓게 하던 구조를 버리고
> **서버가 제공하는 고정 집계 지표를 고르게 하는 구조**로 다시 짜는 중이며, 서버 API는
> 이미 나와 있고 화면 작업이 남았다"고 설명한다
> ([`architecture/06-ops-flows.md`](architecture/06-ops-flows.md) §5).

### 챗봇 — 대화 회수와 관리자 개입

**25. 회수 소진 → 관리자 초기화 → 즉시 재개**
고객 웹에서 챗봇을 열고 남은 회수가 줄어드는 것을 보여주면서 기본 한도(10회)를 소진시킨다.
소진되면 입력이 잠기고 상담 연결을 권하는 안내로 바뀐다. **화면을 그대로 둔 채** 관리자 웹
`/chatbot`으로 이동해 해당 세션을 찾아 **초기화**하거나 **보너스 회수를 부여**한다. 고객 웹으로
돌아와 **새로고침하지 않고** 곧바로 다음 질문을 입력한다.
> 여기서 보여줄 것: 관리자 조작이 다음 메시지부터 즉시 반영되는 것. 포인트는 "빠르다"가
> 아니라 **잔여 회수를 클라이언트가 들고 있지 않다**는 설계다 — 매 메시지가 서버에 물어보므로
> 푸시도 폴링도 없이 전파가 즉시다. 세션 목록의 **최근 접속 IP** 칸도 같이 짚어주면 좋다 —
> 고객 웹이 워커에서 돌아 서버가 보는 주소가 무의미해지자 **워커가 본 실제 클라이언트 IP를
> 헤더로 넘겨 기록**하게 만든 값이다. 정리가 필요하면 **세션 삭제**로 목록에서 치울 수 있다
> (삭제는 회수를 돌려주는 조작이 아니라 행을 지우는 조작이다).
> 시간이 남으면 상담 연결 버튼을 눌러 **연결 전 필수 문진**(카테고리 → 관련 주문 → 상세 설명)이
> 다 채워지기 전에는 연결 버튼이 열리지 않는 것도 함께 보여준다.

### 멀티플랫폼 마무리

**26. WPF 데스크톱**
`ssw-e-commerce-demo-admin-windows`를 실행해 로그인 창 + 메인 창 7개 탭(대시보드 · 주문
관리 · 상품 관리 · 리뷰 관리 · 매장 관리 · 문의 답변 · 감사로그)을 돌아본다.
`seller@demo.ssw`로 로그인하면 리뷰 관리가 조회는 되지만 블라인드 전환 버튼은 없는
(ADMIN·CUSTOMER_SUPPORT 전용) 읽기 전용 상태를 보여줄 수 있다.
> 여기서 보여줄 것: 관리자 웹과 같은 백엔드를 바라보는 PC 네이티브 앱, 역할별 쓰기 권한
> 차이.

**27. 플로팅 메뉴 애니메이션 설정**
`/settings`의 "플로팅 메뉴 레이아웃"에서 부채꼴 · 세로 스택 · 그리드 3종을, "등장
애니메이션"에서 페이드 · 팝 · 슬라이드 3종을 바꿔가며 플로팅 메뉴에 적용해본다.
> 여기서 보여줄 것: 설정이 즉시 반영되는 것 — 앱 재시작이 필요 없다.

**28. 다크모드**
`/settings`의 "테마"에서 라이트 ↔ 다크를 전환하고, 원하면 테마 색상(블루 · 바이올렛 ·
에메랄드 · 로즈 · 앰버 · 슬레이트) 6종도 함께 보여준다.
> 여기서 보여줄 것: 다크모드가 예외 없이 전체 화면에 일관되게 적용되는 것.

## 4. 시연 팁 · 주의사항

1. **결제와 소셜 로그인은 가상 연동이다 — 시작 전에 먼저 밝힌다.** SSW PAY는 실제 결제사로
   나가는 호출이 전혀 없는 가상 PG 모달이고, 소셜 로그인 4종도 공급자로 나가지 않고 "콜백
   성공을 가정한" 모달로 대체돼 있다(배송사 연동도 목업). 외부 API 키·시크릿을 데모에 끌고
   들어오지 않으려고 **의도적으로 자른 경계**라고 설명하는 편이, 나중에 질문으로 나오는
   것보다 낫다. 반대로 **인증·이미지·상담 채팅은 목업이 아니라 공용 인프라에 실제로 위임**한
   실동작 연동이다 — 이 둘을 섞어 말하지 않는다.
2. **LLM 서버가 꺼져 있으면 챗봇이 "AI 오프라인 · 데모 안내" 상태로 넘어간다 — 이것도
   시연 포인트다.** 숨기지 말고 "지금 AI 서버가 꺼져 있어서 규칙 기반 응답으로 넘어갑니다"라고
   그대로 설명한다. AI 브리핑·문의 초안도 같은 원칙으로 폴백된다.
3. **시연 후 데이터 초기화** — DB를 비우면 서버 재기동 시 `UserSeeder`·`DataInitializer`가
   데모 계정 4종과 상품·카테고리·주문 등 시드 데이터를 자동으로 다시 채운다.
   > ⚠️ 이 초기화 전제는 **로컬 개발용 임시 DB 인스턴스**에 한정된 합의 사항이다.
   > 다른 환경의 DB를 초기화하기 전에는 반드시 그 환경이 임시 인스턴스인지부터 확인한다.
4. **안드로이드 에뮬레이터 기동** — 에뮬레이터에서 로컬 웹·서버에 닿으려면
   `adb reverse`로 두 포트를 포워딩해야 하고, 앱을 띄우기 전에 웹·서버가 먼저 올라와 있어야
   한다. SDK 경로·AVD 이름은 개발 머신마다 다르므로 안드로이드 레포 README를 따른다.

## 5. 애매해서 비워둔 부분

- **LLM 서버 켜짐 여부** — 오너가 수동으로 켜는 방식이라 시연 시점의 상태를 이 문서가
  보장할 수 없다. 발표 직전에 `<자체 LLM 서빙 서버>/v1/models` 응답으로 확인한다.
- **포토 리뷰 이미지 정확한 장수** — 루트 README는 "20장"으로 명시하지만, 이 문서에서는
  상품별 개수까지 재검증하지는 않았다. 시연 스크립트 자체에는 영향 없는 배경 수치라 그대로
  README 값을 참조만 하고 별도로 옮겨 적지 않았다.
- **AI 브리핑·초안의 정확한 출력 문구** — LLM 응답이라 실행마다 문구가 달라진다.
  대본에는 "무엇이 나오는지"까지만 적고 정확한 문장은 적지 않았다.

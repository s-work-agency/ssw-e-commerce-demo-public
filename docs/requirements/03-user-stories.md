# 사용자 스토리 (User Stories)

> 상태: 사용자 목표와 구현 범위 구분 · 최종수정: 2026-10-15

스토리는 사용자 목표다. [구현 현황](04-implementation-status.md)과 [테스트 현황](../testing/README.md)으로
현재 제공 기능과 검증 수준을 확인한다.

## 페르소나
- **고객** — 쇼핑 사용자.
- **ADMIN** — 최고관리자.
- **SELLER_SUPPORT** — 판매지원 스태프.
- **CUSTOMER_SUPPORT** — 고객·배송지원 스태프.
- **(메타) 잠재 고객사** — 시연 관람자. 이 데모의 진짜 청중.

## 고객 스토리
- **US-C1 핵심 구매 플로우**: 상품을 탐색하고 장바구니에 담아 결제(목업) 후 주문 완료·내역을 확인한다.
- **US-C2 인증·계정 귀속**: 이메일로 회원가입/로그인(JWT)하여 주문·리뷰·포인트·찜을 내 계정에 귀속한다.
- **US-C3 리뷰·포인트**: 배송 완료 상품에 리뷰를 작성하고 포인트를 확인·주문에 사용한다. 리뷰 사진은 현재 정적 URL 범위다.
- **US-C4 헬스 리워드**: 걸음 수가 임계에 도달하면 포인트와 알림을 받는다. 미션 쿠폰은 미구현 목표다.
- **US-C5 위치/네이티브**: 매장 안내와 기본 배송지 자동채움을 사용한다. GPS 매장찾기·배송지 GPS 자동입력은 초기 목표다.
- **US-C6 AI 상담**: 자연어로 상품·배송을 묻고 근거 기반 답변을 받으며 필요하면 문진 후 상담원으로 전환한다. AI 불통 때는 폴백 안내를 받는다.
- **US-C7 앱형·테마·알림**: 다크/라이트+accent와 앱형 전환을 사용하고 인앱 알림함으로 주문 상태를 확인한다. Android 푸시는 별도 목표다.

## 관리자/스태프 스토리
- **US-A1 (ADMIN) 총괄**: 허용된 운영 화면과 쿠폰/프로모션·자연어 통계·사용량 관리에 접근한다. 스태프 계정/권한·카테고리 자체 CRUD 전체는 현재 제공 범위가 아니다.
- **US-A2 (SELLER_SUPPORT) 판매지원**: WPF에서 허용된 상품·재고 업무와 CSV를 사용한다. AI 어시스턴트는 실제 연결과 도구 기반 보조를 제공하며 쓰기 권한·확인 절차를 따른다.
- **US-A3 (CUSTOMER_SUPPORT) 고객지원**: `admin-web`에서 주문/배송 상태를 관리하고 고객 문의·리뷰/클레임을 처리하며, 대시보드로 일일 현황을 확인한다.

## 잠재 고객사(시연) 스토리
- **US-D1 테스트 자동화 시연(계획)**: 주요 시나리오의 자동 검사와 실제 UI 검증을 구분해 품질 근거를 확인한다. 다음 E2E 스택은 초기 계획이며 실행 완료 실적이 아니다.
  - 특히 **하이브리드 앱의 웹↔네이티브 경계**(탭 → 웹뷰 → `AndroidBridge`)를 **Appium**으로 넘나들며 자동검증하는 것이 가장 강한 임팩트(업계 난제 영역).
  - 계획 스택: 웹 **Playwright** · 안드 하이브리드 **Appium** · WPF **FlaUI**. 서버 **JUnit** 등 실제 실행 결과는 [테스트 현황](../testing/README.md)과 비기능 8장을 따른다.

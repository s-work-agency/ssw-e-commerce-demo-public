# 기능 요구사항 (Functional Requirements)

> 상태: 초기 요구사항과 현재 구현 대조 · 최종수정: 2026-10-15

화면·플로우별 기능 요구사항. 우선순위는 완성도 기준(P0 필수 → P1 → P2).
P0~P2는 초기 계획의 분류이며 완료 표시는 [구현 현황](04-implementation-status.md)을 따른다.

## 1. 우선순위 개요
- **P0 (웹 핵심)**: 프로토타입 화면 재현 + HTTP 커머스 + 리뷰/포인트 원장 + JWT 인증 + 안드 네비 브릿지.
- **P1**: 관리자 웹 · 매장 안내 · 공통 Infra 연동 · 배송지 관리 · 1:1 문의 · 운송장.
- **P2**: WPF · 만보기 리워드 · AI 기능. WPF와 챗봇·자연어 통계는 현재 구현 범위에 포함된다.

## 2. 웹 P0 — 화면별 기능 (프로토타입 17화면 유지)
- **홈**: 배너 슬라이더 · 타임세일 카운트다운 · 카테고리 타일(2-depth) · 신상/할인/인기 섹션.
- **카탈로그**: 대분류→소분류 필터 + 가격대 칩 + 정렬 + 상품 그리드.
- **상품상세**: 갤러리 · 색상/사이즈 · 수량 · 찜/장바구니/즉시구매.
- **장바구니 → 체크아웃 → 완료**: 쿠폰(**내 지갑 보유 쿠폰** 기반 — 공용 코드는 등록 후 사용) · 주문요약(상품/배송/할인/포인트) · mock 결제.
- **쿠폰 드랍 발급 정책**: 한번 드랍에 사용한 코드는 이후 일반 코드 등록을 차단한다. 종료·소진 뒤에도 유지하며 기존 지갑 사용·취소 복원은 보존한다(2026-10-15 확정).
- **마이 / 주문내역 / 찜 / 설정** · **인증**(JWT 실제 로그인, 회원가입/로그인). 찜은 **계정 귀속**(서버 wishlists). 주문내역에서 **주문 취소**(pending/paid 한정) 가능. 로그인·가입 성공 후에는 메인(`/`)으로 이동한다.
- **소셜 로그인(목업)**: 네이버 · 카카오 · Google · Meta 4종 버튼을 노출하되 **실제 OAuth2 공급자 연동은 하지 않는다**. "콜백이 성공했다고 가정하는 가상 로그인 모달"로 대체하고, 승인 시 데모 계정으로 실제 로그인을 수행한다(이후 흐름은 실 로그인과 동일). 모달은 가상 연동임을 화면에 명시한다 — SSW PAY 결제 목업과 같은 계열의 의도적 축소다(§9).
- **리뷰**: HTTP 연동(내 리뷰 · 작성가능 목록 · 작성). 사진은 현재 제한된 정적 이미지 URL을 받으며 사용자 사진 업로드 전체가 구현된 것은 아니다.
- **포인트**: 원장(PointLedger) 기반 조회·주문 사용·가입 보너스(+5000)·구매 적립(delivered 시 등급별 1~2%)·취소 환불.

## 3. 카테고리 (2-depth, 대분류 11종 확정)
`Category.parent`로 대분류→소분류 계층을 구현했다. 홈 타일·카탈로그 필터·admin 상품분류에 반영한다.

| # | 대분류 | 소분류(예시) |
|---|---|---|
| 1 | 패션의류 | 상의·하의·아우터·이너/언더웨어 |
| 2 | 패션잡화 | 가방·신발·액세서리·모자·시계/주얼리 |
| 3 | 뷰티 | 스킨케어·메이크업·헤어/바디·향수 |
| 4 | 헬스/건강 | 영양제·건강식품·운동/피트니스·의료용품 |
| 5 | 디지털/가전 | 전자기기·가전디지털·컴퓨터/주변기기·모바일/액세서리·음향/카메라 |
| 6 | 리빙/인테리어 | 리빙·가구·침구·조명/소품·수납 |
| 7 | 주방/생활 | 주방용품·생활용품·청소/세탁·욕실 |
| 8 | 식품 | 신선식품·가공식품·간식/과자·음료·커피/차 |
| 9 | 도서/문구/취미 | 도서·문구/오피스·악기·취미/DIY |
| 10 | 스포츠/레저 | 스포츠의류·아웃도어/캠핑·자전거 |
| 11 | 반려동물 | 사료/간식·반려용품 |

> 유아/출산(유아동의류·완구·수유/이유·기저귀)은 오너 판단으로 접었다 — 데모 구색에서 빼기로 해
> 대분류와 소속 상품 4종을 함께 없앴고, 그래서 대분류가 12종에서 11종이 되었다.
> 상품 번호는 다시 매기지 않는다. 비운 자리는 구색이 얇던 소분류의 새 상품(신선식품·건강식품·
> 침구·반려용품)이 물려받아 일반 상품 시드는 50종이다. 별도의 실험용 4종을 더하며 현재 DB 행 수와는 구분한다. 상품 사진이 번호로 묶여 있어 한 칸만
> 밀어도 남은 상품의 사진이 전부 어긋나기 때문이다.
>
> 이 표는 분류 기획이며 현재 시드는 대분류 11종·소분류 45종이다. 운영 데이터 개수와 동일하다고 보장하지 않는다.

## 4. 관리자 (admin-web)
대시보드(주문/매출 통계) · 주문관리(상태변경 — 상태 전이 이력 기록, **운송장 입력**) · 상품/재고 CRUD · 리뷰/문의 관리(**1:1 문의(inquiries) 처리 포함** — 고객 작성 문의에 답변) · 쿠폰/프로모션 관리 · **챗봇 사용량 관리** · 설정.
- 대시보드는 구현된 백엔드 집계 API를 사용하며 시연 데이터는 DB 시드로 제공한다. 회원/역할 관리와 카테고리 자체 CRUD 전체는 현재 구현 범위가 아니다.
- **챗봇 사용량 관리(`/chatbot`)**: 챗봇 대화 세션 목록을 보고 **사용 회수 초기화**와 **보너스 회수 부여**를 할 수 있다. 관리자 조작이 고객 화면 새로고침 없이 **다음 메시지부터** 반영되는 것까지가 요구사항이다(§8, [`../architecture/06-ops-flows.md`](../architecture/06-ops-flows.md) §4).

## 5. 직원용 데스크톱 (admin-windows / WPF)
대시보드·주문·상품·매장·문의·상담·리뷰·챗봇 관리·감사로그·자연어 통계의 10개 메뉴를 역할에 따라 제공한다.
필터·다중 선택·CSV와 도구 기반 어시스턴트를 구현했다. AI 연결은 SIWC(Sign in with ChatGPT) 또는
OpenAI 호환 서버를 선택하며 사용량·컨텍스트 표시와 수동/자동 압축을 지원한다. 최신 AI/UI 변경은 로컬 구현을
포함하며 실제 모델 왕복·릴리스와 구분한다. 초기 상품설명 생성·감정분석·자동탐지 구상을 모두 완료했다는 의미는 아니다.

## 6. 권한 (3-role)
- **ADMIN** — 최고관리자, 전체 권한.
- **SELLER_SUPPORT** — 판매지원(상품/재고 등록·수정, 입점/정산 문의, 상품 CS). 주로 `admin-windows`.
- **CUSTOMER_SUPPORT** — 고객·배송지원(문의·주문/배송 상태·리뷰/클레임). 주로 `admin-web`.

## 7. 네이티브 / 멀티플랫폼 기능
- **GPS 매장찾기(P1)**: 현재위치 기반 매장 목록+지도+거리. 매장 좌표는 오너가 필요 시 제공.
- **만보기 리워드(hybrid)**: 걸음 임계 달성 → 포인트 적립·알림 구현. 미션 쿠폰 발급은 계획이다.
- GPS 매장찾기·배송지 GPS 자동입력·Android 푸시는 초기 목표이며 현재 완료 범위로 보지 않는다.
- 파일 위임은 관리자 상품 이미지 경로가 구현돼 있다. 리뷰 사진/프로필 업로드 전체와 구분한다.
- ※ 네이티브 기능은 JS 브릿지(`__sswNavigate`/`AndroidBridge`)로 웹에 노출.

## 8. AI-Native · 고객 상담

초기 계획은 "자연어 상품검색 1개를 목업 수준으로"였으나, 실제 LLM 서빙 서버가 붙으면서 **챗봇이 실동작 기능으로 승격**됐다. 가상피팅·음성쇼핑은 여전히 범위 밖(백로그)이다.

- **자문 챗봇(고객 웹)**: 키워드 프리필터 → 분류 게이트 → 미니 RAG → 답변 생성 4단계. 쇼핑 범위 밖 질문은 거절하고, LLM 서버가 꺼져 있으면 **오프라인 폴백**으로 자동 강등된다.
  - 패널을 열 때 LLM 상태를 먼저 조회해 오프라인이면 그 사실을 명시하고 상담 문진으로 유도한다. 이 조회는 **대화 회수를 소모하지 않는다**.
  - 답변은 리트리벌 근거를 우선하고, 상품 추천은 본문에 상품명을 나열하는 대신 **블록 버튼 행**으로 렌더링한다.
  - 로그인 상태에서 배송·주문 의도가 감지되면 **최근 주문 선택 분기**(0건/1건/N건)를 거쳐 실제 주문·상품 데이터를 근거로 답변한다. 주문 선택 버튼도 회수를 소모하지 않는다.
- **대화 회수 제한**: 세션당 기본 **10회**. 잔여 회수는 **서버가 정본**이고(`chat_usage` 테이블), 클라이언트 쿠키에는 세션 키만 둔다. 사용량 서버가 불통이면 **막지 않고 통과**시키되(fail-open) 잔여 표시는 "확인 불가"로 낮춘다 — 가용성이 우선이다.
- **관리자 회수 제어**: 관리자가 세션별로 회수를 초기화하거나 보너스(**+1~50**)를 부여할 수 있고, 고객은 새로고침 없이 **다음 메시지부터** 늘어난 회수를 쓴다(§4). 세션 목록에는 **최근 접속 IP**가 함께 나오고(고객 웹 워커가 헤더로 넘긴 실제 클라이언트 IP — 표시용이지 판정용이 아니다), 필요하면 **세션을 삭제**해 목록에서 치울 수 있다(회수를 되돌리는 초기화와 다른 조작이다).
- **상담원 연결(실시간 채팅)**: 챗봇에서 상담사 1:1 실시간 채팅으로 전환할 수 있다. 상담사 수용량이 제한적이라는 전제로 **연결 전 필수 문진**(카테고리 → 관련 주문 → 상세 설명)을 두고, 문진을 마치기 전에는 연결 버튼이 활성화되지 않는다. 로그인 검사는 상담을 **제안하는 시점이 아니라 "상담 준비" 버튼을 누르는 시점**에 한다.
- **상담 세션 지속**: 대기·진행 중인 상담은 위젯을 닫았다 열어도 상담 뷰로 복원된다(탭 스코프). 챗봇으로 되돌아가는 것은 **명시적 종료로만** 가능하다.
- **관리자 웹 AI 보조**: 대시보드 AI 브리핑 · 1:1 문의 답변 초안. 둘 다 챗봇과 같은 오프라인 폴백 원칙을 따른다.
  - **자연어 통계**는 관리자 웹·WPF에 구현돼 있다. 서버 지표 카탈로그와 허용 파라미터를 검증해 조회하고(`ADMIN` 전용), LLM은 선택과 결과 해석을 맡는다. 추천 질문·결과 표·부분 실패·해석 재시도를 제공하며 최신 UI는 로컬 변경을 포함한다([`../architecture/06-ops-flows.md`](../architecture/06-ops-flows.md) §5).

상세는 [`../architecture/07-auth-and-chatbot.md`](../architecture/07-auth-and-chatbot.md)가 정본이다.

## 9. 가상 연동 (목업) 범위

아래 결제·소셜 공급자·배송사 연동을 가상 연동으로 대체한다. 해당 공급자에게 실제 요청은 보내지 않는다.
공통 Infra·자체 LLM 서버·WPF AI 연결에는 실제 외부 의존성이 있다.

| 대상 | 대체 방식 | 화면 표기 |
|---|---|---|
| 결제 (PG) | SSW PAY 가상 결제 모달 — 승인·실패 분기 제공 | "DEMO PAYMENT GATEWAY" · "TEST MODE" 배지 |
| 소셜 로그인 4종 | 콜백 성공을 가정한 가상 로그인 모달 → 데모 계정으로 실제 로그인 | 모달에 가상 연동임을 명시 |
| 배송사 추적 | 운송장 번호·배송사 입력까지만, 조회 연동 없음 | — |

> 인증·파일·실시간 채팅은 목업이 아니라 **공용 인프라에 실제로 위임**한 실동작 연동이다([`../architecture/09-infra-integration.md`](../architecture/09-infra-integration.md)). 목업 범위와 혼동하지 않는다.

# 프로젝트 개요 (Project Brief)

> 상태: ✅ 확정 · 최종수정: 2026-08-06

## 1. 목적
SSW E-Commerce Demo는 표면적으로 이커머스 쇼핑 앱이지만, 진짜 목적은
**SWorkAgency의 AI 오케스트레이션 + AX(작업 효율) 역량 쇼케이스**다.
"AI 주도 워크플로로 이 완성도의 멀티플랫폼 서비스를 이 속도로 만든다"를 증명하는
**영업·포트폴리오 시연용** 작업물이다.

## 2. 메인 포인트
**멀티플랫폼(웹 + 안드로이드 네이티브 + Windows 데스크톱)** 이 메인이다.
- **웹**: 프로토타입 충실 재현 + 앱형 UX.
- **안드로이드**: WebView 셸에 네이티브 기능(GPS·만보기·매장위치)을 붙여 모바일 네이티브 역량 시연.
- **Windows**: 직원용 WPF 데스크톱 앱(`admin-windows`)으로 PC 네이티브 관리 역량 시연.

보조 포인트:
- 앱형 UX (페이지 전환 애니메이션·앱형 오버레이)
- 테마 커스터마이징 (다크/라이트 + accent 6종, 실시간 전환)
- 개발과정 투명성 (AI 오케스트레이션 로그 자체가 AX 증거)

포인트 우선순위: ① 멀티플랫폼 ② AI 오케스트레이션 개발방식 ③ 앱형 UX 완성도.

## 3. 타깃
잠재 고객사 (개발 외주·AI 도입 검토자). 어필 축 = 속도·완성도·멀티플랫폼·AI 워크플로.

## 4. 도메인
종합몰. 카테고리는 지속 확장하며, 상위 **대분류를 추가해 2-depth 계층**으로 묶는다.

## 5. 인프라 서사
멀티클라우드(Cloudflare + GCP)·공용 마이크로서비스(인증/알림/파일)까지 프로덕션급 인프라를
AI 오케스트레이션으로 구성 → "데모지만 실제 운영 아키텍처"라는 서사 강화.
배포도 손이 아니라 파이프라인이 한다 — 프런트는 깃 연동 빌드 게이트, 서버는 키 없는 연합 인증과
터널 접속으로 자동 배포되고, CI에 보관하는 시크릿은 0개다.
(배포 상세 문서는 이 공개본에 포함하지 않는다)

## 6. 확정 사항
- **플랫폼(5종)**: `web`(고객 웹) · `server`(백엔드) · `android`(고객 안드로이드) · `admin-web`(관리자 웹) · `admin-windows`(직원용 WPF 데스크톱). ※ `admin-android`(관리자 안드로이드)는 보류(후속 검토).
- **AI-Native 기능**: 자연어 상품검색 1개를 **'추상화·목업' 수준**으로만 제공(실제 LLM 연동 아님). 개인화·챗봇은 후속.
- **카테고리 2-depth**: 지금 도입.
- **제외**: AI 제작과정을 앱 UI에 직접 노출(About/메이킹·Developer Mode 토글)하는 기능은 넣지 않는다.

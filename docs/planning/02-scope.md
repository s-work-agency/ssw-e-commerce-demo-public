# 범위 (Scope)

> 상태: 초기 우선순위와 현재 구현 대조 · 최종수정: 2026-10-15

P0~P2는 초기 기획의 우선순위다. 완료 상태는 [구현 현황](../requirements/04-implementation-status.md)을 따른다.

## 1. 플랫폼 범위 (딜리버러블 5종)
| 딜리버러블 | 설명 | 현황 |
|---|---|---|
| `web` | 고객 웹 (Next.js 16) | HTTP 커머스·챗봇·상담 구현 |
| `server` | 백엔드 API (Spring Boot 3.4.1) | 구현됨 |
| `android` | 고객 안드로이드 (WebView 셸 + 네이티브 하단탭) | 구현됨 |
| `admin-web` | 관리자 웹 | 운영 화면·자연어 통계 구현 |
| `admin-windows` | 직원용 Windows WPF 데스크톱 앱 | 역할 기반 10개 메뉴·AI 도구 구현 |

> `admin-android`(관리자 안드로이드)는 **보류** — 이번 범위 제외, 후속 검토.

## 2. In-Scope

### P0 (MVP 필수)
- 프로토타입 ~17화면 웹 포팅 — **시각·구조 충실 재현**.
- 핵심 커머스 플로우: 홈 → 카탈로그 → 상품상세 → 장바구니 → 체크아웃(**mock 결제**) → 주문완료 → 주문내역.
- 웹↔백엔드 **HTTP 연동**: HTTP가 기본이며 주문·리뷰·포인트 원장·혜택·문의 등을 API로 처리한다.
- **JWT 인증**: 실제 로그인·역할·계정 귀속을 구현했다.
- 안드로이드 **네이티브 네비게이션 브릿지**: `window.__sswNavigate`/`onRouteChanged`로 SPA 전환·탭 동기화를 구현했다.
- **주문 취소**(pending/paid 한정) · **쿠폰 지갑 단일화**(보유 쿠폰 기반 적용) · **찜 계정 귀속**(wishlists).

### P1
- 멀티플랫폼 쇼케이스: **매장찾기(GPS)** · 알림 서버(주문상태/프로모션 + 안드 푸시) · 파일 서버(리뷰사진/프로필 업로드).
- 관리자 웹(`admin-web`) 신규 개발.
- **배송지 관리**(user_addresses) · **1:1 문의**(고객 작성 + admin-web 관리) · **운송장 입력·배송 흐름**(tracking → 상태 전환 → 푸시).

### P2
- **만보기(걸음수) + 커머스 리워드**.
- **AI 기능**: 고객 챗봇·관리자 브리핑/초안·고정 지표 자연어 통계·WPF 어시스턴트 구현.
- 직원용 데스크톱(`admin-windows`) 신규 개발.

> P0~P2 경계는 시연 데드라인이 없으므로 **완성도 기준**으로 자른다. 정확한 우선순위는 [요구사항 문서](../requirements/01-functional.md)에서 확정한다.

## 3. Out-of-Scope (이번 데모 제외)
- 실결제 PG 연동 (현재 mock 결제, status 바로 `paid`).
- 대규모 트래픽/부하 대응 (트래픽 스케일링).
- 개인화 추천·가상피팅·음성쇼핑.
- GPS 자동입력·만보기 쿠폰·Android 푸시 등 초기 목표 중 현재 미구현 범위는 완료로 표시하지 않는다.

## 4. 시연 환경 (보유 운영 문서 기준)
- 프론트 웹 2종(고객·관리자): **Cloudflare Workers**. 깃 연동 빌드가 빌드·배포를 맡는다.
- DB + 백엔드: **Raspberry Pi/K3s**, 커머스 전용 DB와 공통 Infra 경계를 구분한다.
- 배포: 프런트는 깃 연동 빌드, 서버는 별도 패키지·검증·릴리스 절차다. 과거 VM 자동 배포와 혼동하지 않는다.
- 2026-09-22 보유 기록 기준이며, 오늘의 라이브 서비스·배포 revision을 검증한 것은 아니다.
- 배포·운영 정리는 In-Scope, 트래픽 스케일링은 Out-of-Scope. (배포 상세 문서는 이 공개본에 포함하지 않는다)
